# YouTube URL — загрузчик видео

Это мой учебный проект на Python. Я сделал сайт, на котором можно зарегистрироваться, вставить ссылку на YouTube, выбрать доступное качество и скачать видео. У каждого пользователя есть своя история загрузок.

## Что умеет проект

- регистрация и вход в аккаунт;
- получение названия, автора, обложки и доступных разрешений видео;
- скачивание выбранного качества через `yt-dlp`;
- отображение прогресса загрузки;
- просмотр истории и повторная загрузка из неё;
- удаление записей из истории.

## Технологии

- **Python и FastAPI** — серверная часть и страницы сайта;
- **Jinja2, HTML и CSS** — интерфейс;
- **JavaScript** — обновление прогресса загрузки;
- **SQLite** — пользователи и история;
- **Redis** — состояние фоновых задач загрузки;
- **yt-dlp** — получение информации и скачивание видео;
- **FFmpeg** — объединение видео и аудио в один файл.

## Что нужно установить

Нужны Python 3.10 или новее, Redis и FFmpeg. Также понадобится доступ к интернету.

## Как запустить локально

Открой терминал в папке проекта и выполни команды:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Запусти Redis в отдельном окне терминала. Если Redis установлен локально:

```bash
redis-server
```

Затем в первом окне запусти сайт:

```bash
uvicorn app.main:app --reload
```

Открой в браузере [http://127.0.0.1:8000](http://127.0.0.1:8000). При первом открытии сайт предложит войти или создать аккаунт.

Если Redis работает не на этом компьютере, можно указать его адрес через переменную `REDIS_URL`. Путь к базе SQLite можно изменить переменной `DATABASE_PATH`.

## Деплой на Render

В корне проекта есть `render.yaml` и `Dockerfile`. Blueprint создаёт веб-сервис, PostgreSQL и Redis, а Dockerfile устанавливает FFmpeg. На Render приложение использует PostgreSQL, а локально по-прежнему работает с SQLite.

1. Отправь изменения в GitHub.
2. В Render выбери **New → Blueprint** и подключи репозиторий с проектом.
3. Проверь ресурсы Blueprint и нажми **Apply**. Render сам создаст сервисы и сгенерирует `SECRET_KEY`.
4. Дождись успешного деплоя и открой адрес веб-сервиса `youtube-url`.

Секрет сессии хранится в переменных Render и не меняется при обычном перезапуске. Входная cookie подписывается этим секретом, работает только по HTTPS и действует 14 дней. Если вручную изменить `SECRET_KEY`, пользователям нужно будет войти заново.

Если YouTube отвечает `Sign in to confirm you’re not a bot`, это ограничение со стороны YouTube для запросов с сервера Render, а не проблема входа в аккаунт сайта. Можно передать yt-dlp экспортированный cookie-файл YouTube через **Environment → Secret Files**. Назови файл `youtube-cookies.txt` — приложение прочитает его из `/etc/secrets/youtube-cookies.txt`. Не добавляй этот файл в репозиторий и не отправляй его в чат: cookie-файл даёт доступ к аккаунту. Использование cookies аккаунта может привести к временной или постоянной блокировке YouTube-аккаунта, поэтому передавай их только если готов принять этот риск.

Бесплатный Render подходит для демонстрации, но у него есть ограничения: сайт засыпает после 15 минут без запросов, бесплатный диск не сохраняет файлы между перезапусками, Redis может очищаться после перезапуска, а бесплатная PostgreSQL база удаляется через 30 дней. Поэтому скачанные файлы временные, а аккаунты и история сохраняются в базе только до её срока окончания. Для постоянного использования нужна база без срока удаления и надёжное хранилище файлов.

## Как устроены файлы

```text
app/
├── main.py                 # маршруты сайта, аккаунты, история и задачи
├── services/
│   └── youtube.py          # получение форматов и скачивание через yt-dlp
├── static/
│   ├── css/                # стили страниц
│   └── js/app.js           # обновление прогресса
└── templates/              # HTML-страницы
```

Скачанные файлы сохраняются в `downloads/`, а история и аккаунты — в `media_downloader.db`. Эти локальные данные и секрет сессии не отправляются в Git: они добавлены в `.gitignore`.

## Как отправить изменения в GitHub

README уже добавлен в проект. Чтобы отправить текущие изменения в настроенный репозиторий `origin` из ветки `main`, выполни:

```bash
git add README.md .gitignore app requirements.txt
git commit -m "Update downloader and add project README"
git push origin main
```

Перед отправкой можно посмотреть, какие файлы попадут в коммит:

```bash
git status
```
